# v2

The `v2` branch (with ps3recomp's `ascension-v2`) is where the larger rewrites happen. `main` (with `ascension-v0.15`) stays the playable build.

## Why

The first level runs at ~16 fps (see STATUS.md, "Where the level's frame goes"). Targeted fixes to the SPU runtime and the lifter did not move it: the SPU side and the emulated RSX thread are both near their limit, and the lifted SPU code is uniformly slow rather than slow in one place. The rendering also still differs from the game (Kratos' tattoo, shadow acne).

## Plan

1. **Map EDGE in Ascension.** Which job modules run under the EDGE workloads (wid 15-17), which EDGE version, the job's input and output layout, the stages it uses (vertex and index decompression, skinning, culling, output compression) and their cost.
2. **EDGE geometry HLE.** A native C++ implementation of the jobs mapped in step 1, in ps3recomp (`libs/spu_hle/`), next to the lifted path:
   - `PS3_EDGE_GEOM_HLE=1` runs a recognised job natively; an unknown version or variant falls back to the lifted code.
   - `PS3_EDGE_GEOM_CHECK=1` runs both and compares the output byte for byte, logging the first difference.
   - Each title turns it on in its defaults file once a check run shows no difference. A table of recognised EDGE versions and the titles they were checked on goes with the code.
3. **RPCS3's RSX renderer** as a GPU backend for ps3recomp, in place of live draw. RPCS3 is GPL-2: using its code makes the result GPL-2, to be decided before starting.

Each step is measured on its own (the perf panel's SPU/RSX lines and the 80 s level run) and kept only if it helps.

## Found so far

- **Correction (2026-10-19): module 218 is not EDGE's geometry stage but the per-draw command builder.** Decoded from captured jobs: it reads a small header plus a fragment program's microcode, copies the program (constants patched) to GPU-visible memory, and writes the draw's RSX commands (shader program 0x08E4, shader control 0x1D60, texcoord control 0x0B40, and in the second shape vertex array format/offset 0x1740/0x1680, viewport 0x0A20, draw 0x1808 with a 128-byte quad of vertices). ~19,000 jobs a second at ~14 fps is ~1,350 a frame: one per draw call (the window title shows ~3,000 draws a frame). The plan holds -- native code next to the lifted job, with the byte-for-byte check -- with this job as its target; being the engine's own code it carries over less to other titles than an EDGE stage would.
- **The job module 218** (`jobmod_7868e9b847d1`) is run by the workloads named EDGE0-2, 15-17 (`SPU_OVL_WID_HIST=1`). Entry LS `0xAD98`; it returns to the Wws manager at `0x3368`. In the level it runs ~19,000 jobs a second at ~160 us each, ~3 SPU-seconds per second (`SPU_JOBCAP=-,218,AD98`), the largest cost in the game. Two job shapes alternate: one 160-byte GET and two PUTs (368 bytes), or one 336-byte GET and four PUTs (704 bytes); the geometry input is already in local store at entry.
- Other workloads: 8 (audio: modules 204, 205, 223; 204 is the mixer, `brbSpeakers`), 3 (General6: 200, 202), 5 (229), 7 (216), 9 (217), 10 (225), 11 (201), 12 (227), 13 (210), 14 (226), 18 (RsxSync: 221).
- Test cases: `work/edge_cases/menu2` (32 jobs) and `level1` (48 jobs), recorded with `SPU_JOBCAP`; `ps3recomp/libs/spu_hle/tools/sjc_dump.py` reads them.

## Later candidates for native code

Chosen by measured cost (`SPU_JOBCAP=-,<overlay>,<entry>` times any job module), each with the same side-by-side check as EDGE. Sony libraries come first: the work carries over to other titles (God of War III, the God of War Collection, other ps3recomp ports).

| What | Runs today | Idea |
|---|---|---|
| MLAA (the game's anti-aliasing) | five SPU post-process tasks a frame | a GPU shader (MLAA ported, or SMAA/FXAA) |
| Audio mixer (modules 204, 205, 223) | SPU, workload 8 | native mixing, or straight to the host audio API |
| PPU busy waits (`func_00466E28`, `func_00466274`, `func_00416328`) | the main thread spinning on SPU results | real waits that free the core |
| Particle job (SPU images 1 and 3) | SPU tasks | native, if it measures heavy |
| Rendering | live draw | RPCS3's RSX renderer (step 3 above) |
